# 会话记忆验收场景

每组从新会话开始，按顺序发送；记录每轮原问题、补全问题、SQL、结果、耗时和是否符合预期。
这些是待真实模型验证的人工验收用例，不是已通过的准确率报告。结构化上下文及 SQL 可从数据库轮次记录与模型日志核对。

| 组 | 顺序输入 | 核对重点 |
| --- | --- | --- |
| 1 条件追加 | 统计2025年第一季度各大区销售额 → 只看华东 → 再加上订单量 | 时间继承，地区筛选增加，两个指标保留 |
| 2 条件替换 | 统计2025年3月华东销售额 → 改看华南 → 改成2025年2月 | 地区及时间分别替换，不把互斥条件叠加 |
| 3 条件清除 | 统计2025年第一季度华东各品类销售额 → 取消地区限制 → 只看华南 | 先清除地区，再添加新地区 |
| 4 分组修改 | 统计2025年第一季度各大区销售额 → 按月份拆分 → 按品类统计 | 指标和季度保留，分组按明确请求调整 |
| 5 指标追加 | 统计2025年3月销售额 → 再加上订单量 → 再加上销量 | 最终包含三个指标，不丢失前两个 |
| 6 指标替换 | 统计2025年3月各大区销售额 → 指标改为订单量 → 只看华东 | 销售额被替换，时间及分组保留 |
| 7 排序修改 | 统计2025年3月各大区销售额，从高到低排序 → 改为从低到高 → 只取前3名 | ASC 和 LIMIT 3，月份不变 |
| 8 完整新问题 | 统计2025年1月华东销售额 → 统计2025年3月各会员等级订单量 → 只看黄金会员 | 第二轮不残留一月和华东，第三轮继承三月 |
| 9 首轮指代不明 | 只看它 → 我想统计销售额 → 统计2025年3月各大区销售额 | 首轮澄清，不猜对象；补全后才执行 |
| 10 待澄清补充 | 对比这两个 → 华东和华南的销售额 → 统计范围是2025年第一季度 | 保存待确认对象，最终条件无歧义；必要时继续澄清 |
| 11 空结果 | 查询2025年4月订单明细 → 改成2025年3月 → 只看华东 | 四月空结果仍更新上下文，后续可替换月份 |
| 12 失败保护 | 统计2025年3月销售额 → 模拟查询阶段失败 → 只看华东 | 失败不覆盖上一次成功的月份和指标；通过假数据库注入失败 |
| 13 刷新恢复 | 统计2025年3月销售额 → 刷新页面后只看华东 → 按品类拆分 | 会话ID不变，历史恢复，后续条件继承 |
| 14 新会话隔离 | 会话A查询2025年3月华东销售额 → 新会话B查询2025年1月订单量 → B只看华南 | B不继承A的地区、月份和指标 |
| 15 取消与并发 | 发起长查询 → 同ID并发提问 → 取消首轮并等待清理后重试 | 并发请求明确失败，取消不覆盖有效条件，锁可再次获取 |

第12、15组由本地集成或故障注入测试验证，不依赖模型生成特定失败。真实模型验收应另外核对 SQL 的业务口径，不只检查回复是否流畅。
